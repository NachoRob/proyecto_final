Reglas de navegación

  • Si un usuario sin sesión entra a una ruta privada, se le redirige a /login y, al iniciar sesión, vuelve a la página que quería ver.
  • Si un usuario con sesión entra a /login o /registro, se le redirige a /tienda.
  • El navbar cambia según la sesión: sin sesión muestra [Iniciar sesión] [Regístrate]; con sesión muestra Tienda, Vender, su foto/nombre y [Cerrar sesión].
  • Datos de sesión en el frontend: token (localStorage) y user = { id, name, email, picture } (AuthContext). Los favoritos del usuario viven en FavoritesContext.

4. Tablas de la base de datos y relaciones

RelaciónTipoDescripción
users → posts1 a NUn usuario publica muchos instrumentos; cada publicación tiene un único vendedor. ON DELETE CASCADE.
categories → posts1 a NCada publicación pertenece a una categoría (Guitarras, Bajos, Baterías y percusión, Teclados y pianos, Cuerdas frotadas, Otros).
users ↔ posts (vía favorites)N a NUn usuario guarda muchas publicaciones como favoritas y una publicación puede ser favorita de muchos usuarios. La restricción UNIQUE(user_id, post_id) evita duplicados.

El script completo de creación está en backend/db/script.sql (incluido en este .zip).

5. Contrato de datos de la API REST

Base URL: http://localhost:3000 (producción: URL de Render). Formato JSON. Las rutas con 🔒 requieren el header Authorization: Bearer <token>; sin token válido responden 401. Los errores responden { message: String }.

Objeto Post usado en las respuestas: { id: Number, title: String, description: String, price: Number, image_url: String, condition: String, location: String, created_at: Date, category_id: Number, category_name: String, seller_id: Number, seller_name: String }

POST/users Registrar usuario
// request.body
{
  name: String,
  email: String,
  password: String,  // mín. 6
  picture: String    // opcional
}
// 201 Created
{ id: Number, name: String,
  email: String, picture: String }
// 400 faltan datos · 409 email ya existe
POST/login Iniciar sesión
// request.body
{ email: String, password: String }
// 200 OK
{ token: String,
  user: { id, name, email, picture } }
// 400 faltan datos · 401 credenciales inválidas
GET/users/me Datos del usuario logueado🔒
// header Authorization: Bearer token
// 200 OK
{ id, name, email, picture, created_at }
GET/users/me/posts Mis publicaciones🔒
// sin body
// 200 OK
[ Post, ... ]
GET/categories Listar categorías
// sin body
// 200 OK
[ { id: Number, name: String }, ... ]
GET/posts Galería con filtros
// query params (todos opcionales)
?search=String        // título o descripción
&category_id=Number
&order_by=recent|price_asc|price_desc|title_asc
&limit=Number&page=Number
// 200 OK
{ total: Number, page: Number,
  results: [ Post, ... ] }
GET/posts/:id Detalle de publicación
// params: id
// 200 OK
{ ...Post, seller_email: String,
  seller_picture: String }
// 404 no existe
POST/posts Crear publicación🔒
// request.body
{ title: String, description: String,
  price: Number, image_url: String,
  category_id: Number,
  condition: String,   // opcional
  location: String }   // opcional
// 201 Created
Post
// 400 faltan datos · 401 sin token
PUT/posts/:id Editar publicación propia🔒
// request.body: campos a cambiar
{ title?, description?, price?, ... }
// 200 OK  Post
// 403 no es el dueño · 404 no existe
DELETE/posts/:id Eliminar publicación propia🔒
// params: id
// 204 No Content
// 403 no es el dueño · 404 no existe
GET/favorites Mis favoritos🔒
// sin body
// 200 OK
[ Post, ... ]
POST/favorites Agregar a favoritos🔒
// request.body
{ post_id: Number }
// 201 Created
{ id: Number, user_id: Number, post_id: Number }
// 400 falta post_id · 404 post no existe
DELETE/favorites/:postId Quitar de favoritos🔒
// params: postId
// 204 No Content
// 404 no estaba en favoritos
